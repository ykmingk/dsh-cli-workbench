# CLI 工作台 · dsh-cli-workbench

**把本机独立安装的 `claude`（Claude Code）和 `codex`（Codex）两个命令行编程工具，变成一个三栏图形工作台。**

这是一个 [DeepSeek Harness](https://github.com/deepseek-ai) （简称 DSH）插件。装好之后，DSH 左侧栏会出现「CLI 工作台」图标，点进去就是工作台界面——不用再开终端、不用记命令。

> 说明：本插件背后是**你自己机器上**的 `claude` / `codex` 进程，不是云端服务，也不是 DSH 自带的 Claude/Codex 子智能体插件（那两个是 `@deepseek-ai/dsh-subagent-claude-code` / `-codex`）。

## 它解决什么问题

命令行工具很好用，但过程是黑盒：不知道它正在做什么、花了多少钱、改了哪些文件、这一步要不要批准。

工作台把这三件事摊开：

| 栏位 | 内容 |
|---|---|
| 左栏 | 按工作目录分组的会话列表、搜索、新建会话、归档、批量操作 |
| 中栏 | 对话正文（思考与工具过程默认折叠）、逐工具审批卡、执行审计条目 |
| 右栏 | 文件页签与预览、运行状态：真实 token / 费用 / 上下文占用 / 改动文件 |

底部是输入区：任务清单、多行输入、被引用文字的 chip、文件引用、图片与文件附件、斜杠命令、模型与权限档位、发送/停止，以及一行统计读数。

## 安装

### 前提

1. 已安装 **DSH 桌面版**（本插件要求 `engines.dsh` 在 `>=0.2.2-rc.5 <0.3.0` 之间）。
2. 本机装有 **Git**，命令行里能运行 `git --version`（按仓库地址安装时 DSH 会先探测仓库）。
3. 本机已安装并登录 **Claude Code**（`claude` 命令可用）或 **Codex**（`codex` 命令可用）——至少一个。

两个 CLI 只装一个也能用，另一个的按钮会显示为不可用。

### 用仓库地址安装

**这是唯一支持的方式。** 只有按仓库地址装，工作台里的「立即升级」按钮才能用。

```sh
dsh plugin --profile <你的 profile> add https://gitcode.com/yk1900/dsh-cli-workbench.git
```

也可以走图形界面：DSH 左侧栏 **插件** → **添加插件** → 粘贴上面那个地址。

装完 **重启 DSH**（不是刷新页面），左侧栏出现「CLI 工作台」图标。

**用 gitcode，别用 GitHub。** 实测（国内网络）：

| 仓库 | 安装耗时 | 说明 |
|---|---|---|
| gitcode | 约 1.6 秒 | 稳定，`git ls-remote` 探测 1.2 秒通过 |
| GitHub | 1 分 39 秒 | 一路 ECONNRESET / ETIMEDOUT 重试，很多网络下直接连不上 |

gitcode 不在 pnpm 的内置托管商列表里，DSH 会先用 HTTPS 探测仓库；探测不通才改试 SSH
（那时需要配 SSH 密钥）。gitcode 的 HTTPS 是通的，正常不会走到 SSH。

### 之后的升级

装好之后不用再碰命令行。打开工作台 → 右上角 **设置** → **CLI 版本与升级**，
第一行就是这个插件本身的版本：

- 有新版本时按钮是 **「立即升级」**，点一下就会装好，按提示重启 DSH 即可；
- 也可以手动重跑同一条安装命令（实测 1 秒）：

```sh
dsh plugin --profile <你的 profile> add https://gitcode.com/yk1900/dsh-cli-workbench.git
```

> **之前用其他方式装过的**：先删掉 `<profile>\node_modules\dsh-cli-workbench`，再按上面的命令装一次。
> 旧方式会在那里留下联接点，直接覆盖会报 `ERR_PNPM_EPERM`，也无法一键升级。

### 运行要求

| 项 | 要求 |
|---|---|
| DSH | `>=0.2.2-rc.5 <0.3.0`（由 `package.json` 的 `engines.dsh` 声明，版本不符会被直接挡下） |
| 平台 | Windows（10/11）。插件用 `explorer.exe` 打开文件夹、用 `cmd.exe` 拉起 CLI；macOS / Linux 未适配 |
| CLI | 本机需已安装并登录 `claude`（Claude Code）或 `codex`（Codex），至少一个 |
| npm | **可选**。只有「检查最新版本」和「用 npm 升级」会用到；没有 npm 时改用 CLI 自带的 `update` |
| Git | **必需**。安装与「立即升级」都走仓库地址，DSH 会先 git ls-remote 探测 |

### 权限与外部服务

- 在本机拉起 `claude` / `codex` 子进程，工作目录就是会话的工作目录；
- 通过 DSH 的 Web 服务与页面通信（只监听本机回环地址），不向任何第三方服务器上传数据；
- **唯一的外部请求**是「检查更新」：打开设置页时读一次项目仓库的 `package.json` 版本号
  （gitcode 的 contents API），不带任何本机信息；读不到就当没有新版本；
- 会读写本机的会话数据（默认在 `~/.dsh/cli-workbench/`）、输入框里添加的图片与文件（同目录下的 `attachments/`）、你选择的项目目录，以及 `~/.claude` / `~/.codex` 里 CLI 自己的配置；
- 「打开文件夹」会调用系统资源管理器；「立即升级」会执行 `dsh plugin add` 把新版本装上；
  两个 CLI 的升级则调用 npm 或它们自带的更新命令。

### 检查它是否真的能用

点开工作台 → 右上角 **设置** → 「CLI 版本与升级」，这里会实时跑 `claude --help` / `codex --help`，核对插件依赖的命令行参数是否还在：

- 全部齐备 → 正常使用；
- 标红缺某项参数 → 你装的 CLI 版本和插件对不上，见下方兼容性说明。

## 使用

1. 点左侧栏「CLI 工作台」。
2. 顶部选 **Claude Code** 或 **Codex**。**这个高亮就是整个界面的范围**：左栏只列这个助手的会话，「新建会话」也只建这个助手。
3. 选一个工作目录（可以调系统目录选择器）。同一个目录下，两个助手可以各自有会话，互不混排。
4. 描述任务，`Enter` 发送，`Shift+Enter` 换行。还没有会话时直接输入回车，会用当前助手建一个会话，并把这句话作为第一句。
5. Claude 需要权限时会弹审批卡：**允许本次 / 本会话都允许 / 拒绝**（可写理由，超时自动拒绝）。Codex 没有审批通道，只显示执行后的审计条目。
6. 右栏看真实 token、费用、上下文占用、改动文件与预览。

### 图片与文件

输入卡左下角有一个**圆形 +**（跟 DSH 自己 composer 的加号同一尺寸与底色：28px 圆、`--dsw-specific-selector` 底）。三种加附件的方式：

- 点 **+** 打开系统文件选择器（可多选）；
- 截图后直接在输入框里 **Ctrl+V 粘贴**；
- 从资源管理器把文件 **拖进输入卡**（拖动时输入卡会描一圈虚线）；**文件夹也能拖**，但只有桌面应用支持（见下）。

图片在输入框上方排成 64px 缩略图，文件是一枚带名字和大小的卡片，右上角 `×` 移除。只有附件、没有文字也可以直接发送。文件夹显示成一张 folder 卡片。

> **文件夹 / 拖入的文件走路径引用**：桌面应用里 DSH 的 preload 提供 `__DSH_HOST_PATHS__.pathFor()`，工作台拿得到真实绝对路径，就只把路径写进消息正文、由 CLI 自己进去读（不复制，多大都行）。浏览器里没有这个路径桥，文件夹会被拒绝并提示「文件夹只能在桌面应用里拖入」；粘贴和文件选择器来的文件也拿不到路径，会复制进插件的 `attachments/` 目录。

两个 CLI 收到的形态不同，工作台按各自的通道送：

| | 图片 | 其它文件 |
|---|---|---|
| Claude Code | 作为 `image` content block 内联进消息（模型真正看到图） | 落盘后把绝对路径写进正文，由 CLI 自己用 Read 工具读 |
| Codex | `codex exec --image <path>`（首轮与 `exec resume` 同一套） | 同上 |

> Codex 能不能真的"看懂"图，取决于它当前用的模型有没有视觉能力；没有的话它仍能按路径去读文件。

上限：单张图片 8MB、单个**上传**文件 20MB、一次最多 **10 个附件（图片 + 文件合计）**、其中上传部分合计 24MB（路径引用的文件不复制、不占体积额度，但同样计入 10 个）。上传的附件按会话存放在数据目录的 `attachments/<会话 id>/` 下，删会话时一起删；路径引用的文件夹/文件仍在原处，删会话不会动它们。聊天记录里会保留缩略图与文件名。

### 已发出的消息：复制与修改

鼠标移到任意一条消息上，时间戳旁边会出现两个小按钮（平时藏着，键盘聚焦也会显形）：

- **复制**：原样复制正文；用户消息和助手回复都有。
- **修改**（只在你的消息上）：CLI 的转录是只追加的，改不了历史。所以「修改」是把文字放回输入框、光标落到末尾——改完发出去的是新的一条，原消息保留；附件不跟着重发。

### 引用对话里的文字

在对话里**选中一段文字**（同一条消息里），选区上方会浮出一个「引用」按钮。点一下，这段原文就变成输入框里的一枚小引用块，**嵌在正文流里**，后面可以直接接着打字：

```
签名校验已经从 MD5 换成 HMAC-SHA256，旧的兼容分支还在   那这个兼容分支什么时候能删？
└──────────────── 链接蓝（引用）────────────────┘   └──── 正文色（你写的）────┘
```

- 引用块是**链接蓝的文字**（只有原文，没有引号前缀、没有底色和边框，和 DSH composer 一致），后面直接接你打的字，颜色仍是正常正文色。
- 引用块本身不可编辑，但可以整块删掉（Backspace）；想重来就删了重新引。
- 引用插在**你最后打字的光标位置**；还没在输入框里打过字就接在末尾。原文里的换行与缩进会压成一行空格，一段最多 2000 字。
- 输入框现在是 contenteditable（不是 textarea），所以引用才能长得像一块「东西」；粘贴纯文本仍然是无格式的，不会把网页样式带进来。
- 发出去之后，气泡里的引用渲染成浅底 + 左侧竖线的弱化小块；**其余仍是纯文本**——你写的 `*`、`_` 不会被当成 Markdown 语法。
- 老消息里（1.0.46 发出去的）以 `> ` 开头的引用块照旧显示，不会被改写。

### 代码审查（未提交改动）

在左栏**右键任意会话 → 审查未提交改动**，工作台会在这个会话的目录里跑一次审查，报告直接进对话（带结论徽标）：

- **Codex** 用自带的 `codex review --uncommitted`（专用命令，非交互、直接出报告）；
- **Claude** 没有对应命令，工作台先算好 `git diff`，再把「只读这份 diff、不要调用工具」的提示交给 `claude -p`——这样审查不会被审批卡住；
- 报告头写清楚用的什么命令、跑了多久；Codex 的 JSON 结论会抽成 `LGTM` / `N 个问题` 徽标，正文里的 JSON 段被去掉（那段是给机器看的）；
- 前置检查都会明说：不是 git 仓库、没有未提交改动、改动超过 200KB、会话正在跑，都会直接报错而不是白跑一次模型；
- 审查不改任何文件（Codex 用只读沙箱，Claude 只读 diff），最长 10 分钟。

### 运行中排队

会话正在跑的时候直接回车，不会报「正在运行」，而是**排队**：消息挂在输入框上方、**和输入框同宽**，这一轮结束后自动发出。

- **逐条显示内容**：排队列表把每条消息的正文都摆出来，一眼知道还排了什么，不是只给个数；
- **撤回**：每条右侧的 × 是「撤回（不发送这条）」，点掉它就不会发出；
- **修改**：每条右侧的 ✎ 就地展开输入框，改完「保存」；
- **插入**：点列表右上角「插入」（追加到末尾），或悬停某条时点它前面的「＋」（插到这条之前）——原地展开一个带占位提示的输入框，回车加入、Esc 取消，不用猜会落到哪；
- 适合「跑着的时候又想到一句」——不打断当前轮，也不用等它跑完再手动发；
- **只排队文字**：附件要落盘、要算大小，排队期间目录可能变，这种情况会让你等这轮结束再发；
- 最多排 20 条；队列跟着会话落盘，DSH 重启不丢；
- 归档的会话不会被排队消息顶回列表（归档就是「先放着」）。

### 权限档位（让它别再一遍遍问）

每个会话标题栏右侧有「权限：… / 沙箱：…」按钮，点开切换，选完即存：

| Claude Code | 行为 |
|---|---|
| 计划 | 先给方案，不改文件 |
| 默认 | 每个需要权限的动作都问（最啰嗦） |
| 接受编辑 | 改文件不问，其它动作仍可能问 |
| **自动** | 由 CLI 分类器判断，**实测 0 次弹卡，日常推荐** |
| 跳过 | 零询问，全部直接执行 |

| Codex | 行为 |
|---|---|
| 只读 | 可读、可跑只读命令，写入被拒 |
| 工作区写入 | 沙箱内读写工作区，系统其它位置被拒 |
| 完全访问 | 跳过沙箱，命令与写文件都直接执行 |

「所有新会话」的默认档位在设置面板里配，存进插件自己的配置文件，不影响 CLI 的全局配置。

## 两个 CLI 的真实差异

工作台不假装两者一样：

| | Claude Code | Codex |
|---|---|---|
| 输出 | 逐字流式 | item 级整段到达 |
| 审批 | 逐工具审批，卡片三个动作真实生效 | 没有审批通道，只有执行后审计条目 |
| 恢复 | `session_id` + `--resume` | `thread_id` + `codex exec resume` |
| 归档 | 插件内软归档 | 原生 `codex archive` / `unarchive` |
| 费用 | `total_cost_usd` 真实上报 | 只上报 token，**不编造费用** |

## 兼容性

插件套着三个会各自独立升级的东西：DSH、Claude Code、Codex。任何一方升级都可能改掉接口，所以做了三层防护：

| 层 | 机制 | 不兼容时的表现 |
|---|---|---|
| DSH | `package.json` 的 `engines.dsh` | 安装或启用时被 DSH 直接挡下并说明原因，不会装上一个跑不起来的插件 |
| Claude Code | 运行时跑 `claude --help`，核对 9 个必需参数 | 「设置 → CLI 版本与升级」标红列出缺哪个参数 |
| Codex | 核对 6 个必需 + 3 个可选参数，并单独探测 Windows 沙箱后端 | 缺必需参数标红；缺可选参数只标「降级」 |

探测是**运行时**做的，不写死版本号：小版本升级只要参数没变就照常工作，不需要改代码。

本插件开发与实测环境：**DSH 0.2.2-rc.5 / Claude Code 2.1.330 / Codex 0.171.0 / Windows 10 19045**。

> macOS 与 Linux 未验证。Windows 之外的平台按 `codex doctor` 的原生结果处理，未做适配测试。

## 更新

DSH 的插件页只对「插件市场条目」和「npm 包」检查版本，从仓库地址装的插件它不会提示。
所以插件自己查：打开 **设置 → CLI 版本与升级**，第一行就是「CLI 工作台」本身的版本，
有新版本时显示 `当前 v1.0.57 → v1.0.58`。

- **点「立即升级」即可**：Host 会用当初那条安装命令把新版本装上，装完提示重启 DSH；
- 也可以手动重跑安装命令，见「安装 → 之后的升级」；
- 版本号来源是项目仓库的 `package.json`（gitcode 的 contents API，国内直连约 0.5 秒，
  不受 CDN 缓存影响）；读不到时显示「无法检查」，不影响任何功能；
- 只在打开这个设置页时查一次，Host 侧缓存 1 小时，不轮询、不后台请求。
## 数据存在哪

插件的数据都在 DSH 的数据目录下，不会碰 CLI 的全局配置：

```
<数据目录>/cli-workbench/
├── state.json        工作区清单与时间戳
├── sessions/         一个会话一个文件（<会话 id>.json）
├── settings.json     新建会话的默认权限 / 沙箱档位
├── operations.log    增删操作的排查日志（只在排查时看，界面不显示）
├── attachments/      输入框里贴进来的图片与文件（一会话一个子目录，删会话时一起删）
└── mcp/              Claude 审批桥运行时的临时配置
```

**一个会话一个文件**：改一个会话只重写它自己那份，单个文件损坏也只丢那一个会话。
从旧版本升级时，原来的 `sessions.json` 会被自动迁移，并改名成
`sessions.json.migrated-<时间>` 保留，不删除——想回退，把它改回 `sessions.json` 即可。

`operations.log` 每行一条 JSON，记录启动、工作区的新增 / 移除 / 改名、会话的新建 / 删除，
超过 256KB 自动只留最近 500 行。出问题想知道「这行怎么没了」时，直接看这个文件。

`<数据目录>` 按启动方式不同，可能是 `<DSH profile 目录>`，也可能是 `~/.dsh`。
工作台「设置 → 数据存放位置」会直接显示当前用的是哪一个。

这里只存**索引与界面状态**：对话本体始终在 CLI 自己的记录里
（Claude：`~/.claude/projects`，Codex：`~/.codex/sessions`），所以这个目录即使丢了，
对话也不会丢，在终端里 `claude --resume` 照样能接上。

### 从 CLI 导入会话

在终端里直接跑 `claude` / `codex` 建的会话，工作台默认看不见。**设置 → 从 CLI 导入会话** 里点「扫描并导入…」，会列出 CLI 记录里、工作台还没有的会话（标题、目录、时间、大小），勾选后导入。

- **只登记指针，不复制正文**：会话的转录仍留在 `~/.claude/projects` 与 `~/.codex/sessions`，工作台只是记住「这个会话存在」。导入后发消息会用 `claude --resume` / `codex exec resume` 接着原上下文继续。
- 打开导入的会话时，对话里只有一条说明（历史不在工作台里），往下就是新的一轮。
- 工作目录已经不存在的会话会列出来但**不可勾选**（CLI 没法在缺失的目录里 resume）。
- 已经导入过的不会重复出现在列表里；同一目录会自动登记成工作区。
- 导入的会话可以照常删除，而且**删除是真的删**——见下一节。

### 删除会话是真删

在工作台里删除一个会话时，CLI 自己的记录也会一起删掉，不会只在列表里消失：

| CLI | 记录在哪 | 删除方式 |
|---|---|---|
| Claude Code | `~/.claude/projects/<目录编码>/<会话 id>.jsonl`（+ 同名 `tool-results/` 目录） | CLI 没有删除命令，直接按会话 id 精确删这两个 |
| Codex | `~/.codex/sessions/<年>/<月>/<日>/rollout-*-<线程 id>.jsonl`（归档的在 `archived_sessions/`） | `codex delete --force <uuid>`（非交互环境必须带 `--force`，否则它只会报「需要交互终端确认」）；命令失败时按 uuid 直接删 rollout 文件兜底 |

删不掉时会**明确告诉你**，不会假装删干净：确认框关掉后如果 CLI 那边的记录还在，提示条会写「已删除 N 个会话；但 CLI 记录没删掉（原因）」，常见原因是那个 CLI 还在终端里跑着、文件被占用——关掉它再删一次即可。

**归档 ≠ 删除**：归档只是从列表收起来，CLI 的记录仍然保留，随时可以用 `claude --resume` / `codex resume` 接上。

删除前的确认框只报数量（「删除 14 个会话」+ 按钮「删除 14 个」），不逐条列会话标题：十几条既列不全，又会把框撑高，最该看的条数反而不显眼。框里写明删的是**聊天记录、附件，以及 CLI 那边的会话文件**；项目目录里的文件一个都不动，也不会被回滚。

两个 CLI 自己也有清理策略：Claude Code 默认只保留 **30 天**的转录（`cleanupPeriodDays`，可在 `~/.claude/settings.json` 调整）；Codex 没有对应的自动清理，所以工作台删除时会主动删。以本机为例，60 个 Claude 转录约 11.5MB、64 个 Codex rollout 约 7.3MB——单条会话通常几百 KB 到 1MB 出头，长期不清理才会明显涨。

想看当前占了多少：**设置 → 数据存放位置**，路径下面一行就是 `CLI 记录占用：Claude 11.5 MB（63 个）· Codex 7.3 MB（64 个）· 附件 0.8 MB`。打开设置时查一次，Host 侧缓存 5 分钟；统计最多数 2 万个文件，不会因为会话太多把设置面板卡住。

它**不**写 `~/.claude/settings.json`、`~/.codex/config.toml`，也不配置 API Key、Base URL 或代理——那些仍然是你 CLI 自己的事。

> 界面语言：当前只有中文。`locale/*.json` 覆盖的是插件市场里显示的标题与简介，
> 界面文案不读它。

## 开发与本地调试

插件是纯 JS，无构建步骤：

```
index.js              Host 半：会话/工作区/路由/存储/审批/文件 API
lib/claude.js         Claude 适配器：启动参数 + stream-json 事件解析
lib/codex.js          Codex 适配器：codex exec --json 启动参数 + 事件解析
lib/format.js         把两个 CLI 的原始事件变成人能看懂的一行话
lib/util.js           无状态小工具（时间、id、路径、子进程、取值集合）
client.js             客户端半：三栏界面（React.createElement + 自绘 CSS）
mcp-permission.mjs    Claude 权限请求 → 工作台审批卡 的 MCP 桥
cordis.patch.yml      bundle 行声明
locale/*.json         插件标题与描述（zh / en）
docs/DETAIL.md        插件市场详情页正文
test/                 回归用例（node test/run-all.mjs）
```

改完 `index.js` 或 `client.js` 后，**已加载的 JS 模块不会自动换**：需要在插件页把本插件卸载再装一次，或重启 DSH。改 `locale`、`docs` 这类静态资源则刷新页面即可。

Host 侧的 HTTP 接口前缀是 `/cli-workbench/api`，本地联调时可以直接访问，例如：

```
http://127.0.0.1:<DSH 端口>/cli-workbench/api/status
```

返回两个 CLI 的版本与兼容性探测结果。

## 测试

回归用例在 `test/`，纯 Node、无依赖、不需要启动 DSH，也不会碰你的会话数据：

```bash
node test/run-all.mjs     # 或 npm test
```

每个用例自己打印「结果：N 通过 / M 失败」，`run-all.mjs` 汇总；有任何失败时退出码为 1。

用例的写法和普通单测不同：它们**从 `index.js` / `client.js` 里抽出真实源码再执行**（而不是复制一份逻辑），所以改实现时测试会跟着变，不会出现「测试过了但代码早就不是一个东西」。断言覆盖协议解析、路径边界、状态机、以及一批「本来会坏」的写法。

其中两个是**行为级**的（不是字符串断言）：

- `test/route-test.mjs`：用 `Object.create(Workbench.prototype)` 拼一个最小实例，真的走一遍 HTTP 路由——附件从 `/message` 进来、落盘、交给适配器，再由 `/attachment` 回放；顺带钉住 400/403/404/409/413 的每一种拒绝。
- `test/client-flow-test.mjs`：用 React shim 把 App 挂起来，模拟「输入文字 → 选文件 / 粘贴截图 / 拖入文件 → 点发送」，断言真正发出的 POST 体；再让服务端返回 500，断言失败后文字与附件都回到输入框（这是 1.0.45 修的那个坑，旧代码上这条会红）。
- `test/css-test.mjs`：把 `const CSS = String.raw\`…\`` 这段表达式**真的求值**，断言结果是一段等于源码文本的字符串。CSS 注释里出现未转义的反引号会把模板提前截断，文件语法仍然合法、界面照常渲染，只是 `CSS` 变成数字——**整个工作台没有样式**（1.0.46 第一版就是这么翻的，类名断言全绿）。
