# CLI 工作台

把本机**独立安装**的 `claude` 与 `codex` 两个命令行编程工具，翻译成一个三栏图形工作台。界面背后是用户自己机器上的 CLI 进程，不是远程服务，也不是 DSH 的 Claude/Codex 子智能体插件。

## 在哪里

DSH 左侧栏会出现「CLI 工作台」图标，点击后整页切到工作台：

- **左栏**：按工作目录分组的会话、搜索、新建会话、归档与批量操作。
- **中栏**：对话正文为主，思考与工具过程默认折叠；正文最后一行是「正在做什么」的运行状态；Claude 的逐工具审批卡、Codex 的执行审计条目。
- **右栏**：文档式标签条——「文件」固定页签 + 打开文件的文件名页签 + 运行状态；窗口较窄时收成浮层。
- **底部输入区**：任务清单（有 CLI 待办时）+ 多行输入、文件引用、斜杠命令、模型与权限模式、发送/停止 + 一行居中统计读数。

## 两个 CLI 的真实差异

| | Claude Code | Codex |
|---|---|---|
| 输出 | 逐字流式（`--include-partial-messages`） | item 级整段到达 |
| 审批 | 逐工具审批：走 `--permission-prompt-tool` 的 MCP 审批工具，卡上三个动作真实生效 | 没有审批通道，只有执行后的审计条目 |
| 权限 | `--permission-mode`：计划 / 默认 / 接受编辑 / 自动 / 跳过 | 沙箱档位：只读 / 工作区写入 / 完全访问 |
| 恢复 | `session_id` + `--resume` | `thread_id` + `codex exec resume` |
| 归档 | 插件内软归档（`claude --resume` 仍可见） | 原生 `codex archive` / `unarchive` |
| 费用 | `total_cost_usd` 真实上报 | 只上报 token，不编造费用 |

## 使用

1. 点左侧栏「CLI 工作台」。
2. 顶部点 Claude Code 或 Codex 选中一个助手——**这个高亮就是整个工作台的范围**：左栏只列它的会话和装着它会话的工作区，「新建会话」也只建它。
3. 选工作目录（可调系统目录选择器）。同一目录里 Claude 与 Codex 可以各有自己的会话，互不混排。
4. 描述任务，Enter 发送，Shift+Enter 换行。还没有会话时直接输入并回车，会按顶部选中的助手建一个会话并把这句话作为第一句。
5. Claude 遇到需要权限的工具会弹审批卡：允许本次 / 本会话都允许 / 拒绝（可写理由，超时自动拒绝）。
   - 选「本会话都允许」后，该工具会记在右栏「本会话已放行」里，可单条撤销；之后每次自动放行都会在对话里留一条说明。
6. 中途断连或失败时，错误卡上有「重新连接并重试上一条」（Claude 用 session id、Codex 用 thread id 续聊）与「查看诊断摘要」。
7. 右栏看真实 token、费用、上下文占用、改动文件与预览。

## 助手是作用域，不是标签

早期版本按「顶部高亮决定新建会话归谁、左栏却把两个 CLI 的会话全列出来」，会出现「在 Codex 工作区点新建，结果建出 Claude 会话」。现在的规则只有一条：

- 顶部选中 Claude Code → 左栏只有 Claude 的会话与工作区，「新建会话」只建 Claude；切到 Codex 同理。
- 切换助手时当前会话改成该助手最近动过的那个；没有会话就停在空态（不会自动弹新建框）。
- 另一个助手还有会话时，左栏底部给一句提示「另有 N 个 X 会话，切到顶部查看」，不会让人以为会话丢了。
- 跨助手的审批不会静默：顶部提醒条会出现「某助手有会话等你确认」，点「切过去处理」会连助手一起切过去。
- 工作区登记按**目录**存，所以删掉一个工作区会把该目录下两个助手的会话都落到「未分组」；删除确认框里会写明另一个助手还有几个会话。
- 新建会话对话框不再提供助手二选一（那正是分裂的来源），只显示当前助手并提示怎么换。

## 权限：让它别再一遍遍问

每个会话标题栏右侧有一个「权限：… / 沙箱：…」按钮，点开即可切换档位，切换会存进该会话：

| Claude Code | 行为（本机实测） |
|---|---|
| 计划 | 先给方案，不改文件 |
| 默认 | 每个需要权限的动作都弹审批（最啰嗦） |
| 接受编辑 | 文件修改直接执行，其它动作仍可能询问 |
| 自动 | 由 CLI 分类器判断，实测一次都没弹（推荐日常使用） |
| 跳过 | 完全不再询问，所有动作直接执行 |

| Codex | 行为（本机实测） |
|---|---|
| 只读 | 可读文件、可跑只读命令；写入与联网被拒 |
| 工作区写入 | 沙箱内读写工作区，系统其它位置被拒；后端不可用时工作台自动改用 unelevated |
| 完全访问 | `danger-full-access`：命令与写文件都直接执行，不再询问 |

> Codex 走的是 `codex exec --json`（非交互），**没有向用户提问的通道**：所以它不会像命令行里那样一遍遍问你，而是"能执行就执行、不能执行就直接拒绝"。工作台里因此不出现审批卡，只出现执行后的审计条目。
>
> 因此 **Codex「完全访问」 ≈ Claude「跳过」**，而不是「自动」：「自动」仍由 CLI 判断并在必要时拦下，完全访问则一律放行。
>
> 「工作区写入 / 只读」是否可用由工作台启动时执行 `codex doctor`、读取其中的 `sandbox backend` 决定：Codex 0.170 在非交互模式下默认把它解析成 `disabled`，此时工作台会自动追加 `-c windows.sandbox="unelevated"`（受限令牌，无需管理员）并复探一次；只有复探仍不可用，才在菜单与默认设置里标灰为「本机不可用」。设置面板可强制 `unelevated` / `elevated`（elevated 首次运行需要管理员授权）。

想一次改掉"新会话都别再问"，进设置面板 →「新建会话默认权限」，分别选 Claude 的默认档位与 Codex 的默认沙箱，保存后**之后新建的会话**直接继承；已有会话不受影响。默认值存在 `cli-workbench/settings.json`。

## 用量统计放在哪

token 用量、缓存命中、上下文占用、token 速度不在右侧检查器里，而是**输入框下方单独一行紧凑读数**（照 DSH 自己 composer 底部统计 pill 的结构）：这一行与输入卡同宽、居中分散排列，点开是小面板，不占正文空间。

- 运行统计 pill：`3 轮 · 7 步 · 42.1 tok/s`，点开看轮/步、本轮耗时、解码耗时、速度
- token 用量 pill：`25.7K · 缓存 97%`，点开看缓存命中、输入、缓存读取/写入、输出、思考、花费、模型（图标用数据库样式，**不用¥/$ 之类的钱符号**——token 不是钱）
- 上下文 pill：`上下文 62%`，图标是一圈**进度环**，占用越高弧线越长，超过 80% 变警示色；点开看已用/窗口/剩余
- 窗口偏窄（右栏展开）时自动收紧间距与字号，三个读数仍保持一行。

**上下文窗口从哪来（不猜）**：

- Claude：`result` 事件的 `modelUsage[<model>].contextWindow`（本机实测 `983000`），已用 = `input_tokens + cache_read_input_tokens`。
- Codex：`codex exec --json` 的 stdout **没有**窗口大小，但 Codex 自己会把每轮写进 `~/.codex/sessions/年/月/日/rollout-<时间>-<thread_id>.jsonl`，其中的 `token_count` / `task_started` 事件带 `model_context_window`（本机实测 `996147`）。Host 按 `thread_id` 找到这份记录读窗口与最后一次请求的输入 token；文件比 `turn.completed` 晚落地时会补读一次（不轮询）。
- 两个 CLI 都读不到窗口时**不编百分比**：pill 只显示 `上下文 14.9K`（已用 token），明细里写「CLI 未上报」。绝不按模型名猜一个窗口出来凑进度环。

速度只在 CLI 真的上报了解码耗时时显示（Claude 有 `--include-partial-messages` 的逐字流，可测真实解码时长；Codex 非交互只给整段，所以不显示速度，不编造）。

只想让某一个工具别再问，用审批卡上的「本会话都允许」，之后可在右栏「本会话已放行」里撤销。

## 技能、计划模式、Goal

- **技能选择器**：输入框工具条的 ✨ 按钮扫这些位置，列出两边各自的技能（读 `SKILL.md` 的 `name` / `description`，支持 `>`、`|-` 折行）：
  - `~/.claude/skills`、`~/.codex/skills`（用户级）
  - `<工作区>/.claude/skills`、`<工作区>/.codex/skills`（工作区级）
  - 目录链接 / junction 装进来的技能也能扫到（以前 `Dirent.isDirectory()` 对链接返回 false，整片被跳过）。
  - Codex 自带技能在 `.codex/skills/.system`（隐藏目录）：会列出来并标「内置」；找不到描述时标「无描述」，不会从列表里消失。
  - 点选只是把「使用技能 X + 技能说明 + 路径」插进输入框，**不自动发送**，也不替 CLI 编造调用协议。
- **计划模式**：输入框工具条的清单图标是会话级开关，标题栏显示「计划中」。打开后**下一条消息前面**追加一段「先给计划、别改文件」的指令，发完自动关。
  - 这是 prompt，不是 CLI 开关：Codex 没有 plan flag。Claude 另有真正的 `--permission-mode plan`（会话标题栏的「权限」里可切）。
- **Goal**：Claude 的斜杠菜单放行 `/goal`（Claude 原生）。Codex 没有 goal 概念，菜单里不出现、界面里不伪造。

## 自定义规则（CLAUDE.md / AGENTS.md）

不需要另造「系统提示词」——两个 CLI 各自的官方入口就是这两个文件，写一次、之后每次对话都生效：

| 文件 | 谁读 | 位置 |
|---|---|---|
| `CLAUDE.md` | Claude Code | `<工作区>/CLAUDE.md`、`~/.claude/CLAUDE.md` |
| `AGENTS.md` | Codex | `<工作区>/AGENTS.md`、`~/.codex/AGENTS.md` |

两个文件是**各自 CLI 专属**的：右栏和编辑器都只显示当前会话那个助手的那一个（Claude 会话只看 `CLAUDE.md`，Codex 会话只看 `AGENTS.md`），不把另一个的文件摆在一起当噪音。

**两级都列出来。** 右栏「运行状态 → 指令文件」逐条显示：项目级（当前工作目录）和用户级（家目录），各自带「已加载 / 未找到」。只列项目级的时候，家目录里明明有 `CLAUDE.md`，这一栏还是写「未找到」，很容易看成「CLI 没读到任何指令」。

右栏「指令文件」里的**编辑自定义规则**打开编辑器，四个位置一次都能读写（没有的显示「新建」）。内容**原样写入**、不做格式转换，也不把口语改写成别的模板；「插入中文模板」只给一个空白起手式。

## 会话右侧的轮次条与「最新」

- 会话右缘一列短横刻度，每条代表**你发过的一条消息**；悬停显示那条消息与时间，点一下滚到它，当前所在的那条高亮。
- 这是导航，不是搜索：文字原样截断，不重写。
- 滚离底部超过 240px 时，会话内容的**右下角**（滚动区内、输入框正上方）出现一个**只有箭头**的悬浮按钮，点一下回到最新消息。位置本身说明了它是「回到底部」，所以不再挂「最新」两个字。
- 切到别的会话、从别的面板切回来、**甚至退出插件再进来**，都直接落在最新一条：
  - 退出插件再进来时，当前会话 id 早就从本地存储恢复了，而会话内容是异步到的——旧版只监听 id，历史到齐那次不会再跑，于是停在这段对话最早一屏。现在把「历史到齐」也写进依赖，并且跟随状态用 ref 记住。
  - 用户自己往上翻就松开跟随（`pinnedRef`），新消息不会把他拽回底部。

## 复制 Session ID（排查问题用）

会话右键 →「复制 Session ID」，复制两行：

```
CLI 工作台: cw_mwofiem01d3b24
Codex thread_id: 01a1f75d-e32c-7be2-bb09-32821fd27e79
```

Claude 会话第二行是 `Claude session_id:`。原生 id 在发出第一句话之后才有。

## 失败与提醒：Codex 的两种噪音

- **工具失败**：Codex 把错误正文放在事件的 `error` 字段里（`result` 是空的）。工作台现在把这段正文取出来，失败卡上**直接摊开显示**，不用展开「诊断摘要」。
- **CLI 提醒**：像 `Under-development features enabled: async_compaction…` 这种每轮都会出现的警告，不是本轮失败。它不再变成对话里的红色错误卡，而是收进右栏「运行状态 → 运行提示」，会话状态不受影响。
- 「Codex 无逐工具审批通道，此处是执行后的审计记录」这句话从卡片正文挪进了鼠标悬停提示，长任务里不再反复刷屏。

## 右侧栏

- 右栏宽度可拖（左缘把手，240px 起，最多让中栏保留 520px），双击复位；宽度记在 localStorage。
- 「文件 / 预览 / 运行状态」跟随当前会话所属的 CLI：切会话会清掉上一个会话的预览、重读本会话的文件树。
- 预览按文件类型分四条路：
  - **Markdown**（`.md`）按文档排版：标题、列表、引用、代码块、分隔线。
  - **HTML**（`.html` / `.htm`）用沙箱 iframe 直接渲染成页面，脚本能跑；`sandbox` 里**不给** `allow-same-origin`，所以页面读不到 DSH 自己的数据。
  - **代码与其他文本**（`.js` `.ts` `.tsx` `.py` `.ps1` `.sh` `.css` `.json` `.yaml` `.toml` 等）等宽显示，规格行会标出语言。
  - **图片**（`.png` `.jpg` `.gif` `.webp` `.bmp` `.svg`）内嵌 data URL 显示。
  - 目录列出第一层（最多 200 项）。
- **二进制一律不预览**：`.exe` `.dll` `.zip` `.pdf` `.docx` `.class` `.node` 等按扩展名直接判死；没有扩展名但从内容看像二进制的（控制字符过多）也一样。超过 1MB 的文本文件也不预览。
- **Markdown 按文档渲染**：标题、列表、引用、代码块、分隔线都按正文排版，铺满右栏并自己滚动——不是把几百行源码塞进 132px 的小框。
- 文件树里的**相对路径也能打开**（按会话工作目录解析），越出工作区的路径照样拒绝。
- CLI 改动了正在预览的文件时，右栏会自动重读，不会停在旧内容。

## 任务清单

长任务里 CLI 自己给出的待办会显示成可折叠的「任务清单」卡，**钉在输入卡上方**——DSH 的 `conversation.input.dock` 就是放 TodoPanel 的位置：

- Claude：读 `TodoWrite` 工具调用的 `todos`。
- Codex：读回复里的 `- [ ]` / `- [x]` 清单（至少两条才成卡）。
- 读不到就不画——插件不凭猜测替 CLI 编一份待办列表。
- 默认收起，只有一行「任务清单 · 已完成 2 · 进行中 1 · 待办 2」，点开才摊开。

## 「正在执行的工具」显示在哪

跟 DSH 一样：**在对话正文的最后一行**，不是输入框上方的一条状态条。

- DSH 自己的做法：`RunningStatus` 挂在当前轮内容之后，写「深度思考中 / 已工作 1 分 20 秒」；工具调用本身以轮次内的过程卡出现在正文里。输入框上方那块位置 DSH 留给**任务清单 / 队列**（`conversation.input.dock`）。
- 所以本插件的状态行也搬到正文末尾：`⟳ 命令 · Bash  npm test -- auth  1 分 12 秒`，只读，点了不会有任何副作用。
- 完整面板（审批、工具清单、进程、运行提示、项目指令文件）仍在右栏的「运行状态」页签里，点右栏标签条右上角那个图标进去。

## 后台进程与「连接中断」

- 面板切走时 DSH 会卸载本插件的客户端，并回收插件（回收会杀掉 CLI）。现在只有**没有活**时才回收：跑着的回合、等待中的审批、打开的事件流、正在进行的 CLI 升级都算「有活」，会推迟回收并每 30 分钟复查一次；客户端重新挂载的 `/unmount-cancel` 也照样生效。
- 所以从别的面板切回来、或在同一个工作台里切会话，都不会再打断正在跑的任务。
- 真正卸载插件或退出 DSH 时仍然立即回收。

## 输入区

输入卡左下角一排控件：

- `@` 引用项目文件、`/` CLI 斜杠命令（28px 方形图标按钮）
- **技能**：胶囊按钮，图标是锤子；点开列出该助手能用的本地技能
  - 选中后**输入框里只出现一个技能卡片（只写技能名）**，跟 DSH 一样。技能的说明与 `SKILL.md` 路径由工作台在**发送时**补进去，输入框不会被几千字的提示词淹掉。
  - **同名技能各用各的**：`a-share-daily-review` 这种在两个 CLI 目录下都有副本的技能，展开时只取**当前会话所属 CLI 的那一份**（Codex 会话拿到的一定是 `~/.codex/skills/...`）。
  - 想取消就点卡片上的 ×，草稿里那个 `/名字` 令牌一起删掉；手动删掉令牌则不会带上技能。
- **计划**：胶囊按钮，图标是记事本；会话级开关，打开后标题栏显示「计划中」
- 右侧是当前模型选择器与发送/停止按钮
- 技能与计划都用「图标 + 文字」的胶囊（32px 高、18px 图标），和 DSH 菜单那一排同一种语言。
- `@` / `/` / 技能三个浮层**跟输入卡同宽**（DSH 的 trigger menu 就是 `left:0; right:0` 贴着输入卡），一行里左边是文件名/技能名、右边是目录或说明；目录从尾部省略，长路径也看得见离文件最近的那一层。
- 发送键 34px 蓝色圆底 + 白箭头；**停止键是同一个蓝底 + 白色圆角方块**（DSH 的 `.primary` 就是这样），不是整颗白色。
- 输入卡、统计行、任务清单**宽度一致，并且跟着中栏自适应**：`min(100%, clamp(712px, 64% + 32px, 952px))`——跟 DSH 的 `--dsh-composer-card-max-width` 同一个算法。右栏拉宽时输入框自动变窄，右栏收起时自动变宽。

## 版本兼容

插件背后是三个会独立升级的组件，任一升级都可能改变它依赖的接口：

- **DSH**：`package.json` 声明 `engines.dsh = ">=0.2.2-rc.3 <0.3.0"`，不满足时安装/启用会被 DSH 挡下并说明原因，不会装上一个跑不起来的插件。
- **Claude Code**：启动时核对 9 个必需参数（`--output-format`、`--input-format`、`--verbose`、`--permission-mode`、`--permission-prompts`、`--permission-prompt-tool`、`--include-partial-messages`、`--mcp-config`、`--resume`）。
- **Codex**：核对 6 个必需参数与 3 个可选参数（`archive` / `unarchive` / `delete`，缺失只降级为软归档），并单独探测 Windows 沙箱后端。

当前实测通过：DSH `0.2.2-rc.3`、Claude Code `2.1.328`、Codex `0.170.0`。探测在**运行时**做，参数没变的小版本升级无需改代码；缺参数时「设置 → CLI 版本与升级」标红列出缺项，打开工作台时提示一次。完整矩阵见仓库根目录的 `COMPATIBILITY.md`。

## 数据与隐私

- 会话记录保存在当前 DSH profile 的数据目录 `cli-workbench/sessions.json`，只在本机。
- CLI 进程由本机 `claude` / `codex` 可执行文件启动，环境变量沿用当前 DSH 进程；不会上传会话内容到第三方。
- Claude 会话复用同一个 CLI 进程以支持多轮；空闲 10 分钟后进程会被回收，下一条消息用 `--resume` 恢复；删除会话或卸载插件会终止对应进程。
- 审批超时（5 分钟）自动拒绝，避免进程一直挂着。

### 排查日志 `operations.log`

同一个数据目录下还有一个 `operations.log`，**只给排查用，界面上不显示、也没有接口能读它**。

- 记录什么：启动（数据目录来源、当时的会话与工作区数量）、工作区的新增 / 移除 / 改名、会话的新建 / 删除。每行一个 JSON，带毫秒时间戳。
- 为什么有：增删在界面上没有痕迹，「这行怎么没了」只能靠猜。有了它，直接查到「什么时候、哪个目录、什么操作」。
- 体积：超过 256KB 自动只保留最近 500 行，可以一直留着不管。
- 写失败绝不影响主流程（`try/catch` 全包）。

## 工作区的增、删与撤销

- **添加**：左栏标题栏的文件夹图标，选一个目录即可登记为工作区；也可以在某目录里新建会话（会自动登记）。
- **移除**：右键工作区 → 移除工作区。目录和会话都不动，会话落到「未分组」，之后仍可从那里再登记回来。
- **撤销**：移除后的提示条上带「撤销」，点一下用原来的显示名加回来。

## 草稿按会话隔离

每个会话（以及还没建会话的空白输入框）各自保存一份未发送的草稿。切到别的会话不会把上一段文字带过去；切回来还能接着写。输入框高度会随草稿内容重算。

## 已知边界

- 右栏照 DSH 的形式做成**文档式标签条**（不是四个等宽大按钮）：「文件」是固定页签，打开的文件按文件名各占一个页签，宽度跟内容走，点 × 关闭并退回「文件」。拉宽右栏时标签条不会散成四大块。
- **「正在执行的工具」显示在对话正文最后一行**（跟 DSH 的 `RunningStatus` 同一位置），不是输入框上方的一条状态条；输入框上方那块位置留给任务清单（DSH 的 `conversation.input.dock`）。状态行只读，点它不会开关右栏；完整面板在右栏「运行状态」。
- 预览顶部只有一行：`文件名` + 右侧三个小图标按钮（另存 / 外部打开 / 定位文件），鼠标悬停有文字说明。
- 「回到最新」按钮钉在中栏右下角（输入框正上方），**只有箭头**、不随内容滚动：它挂在滚动区外层的定位层 `.cw-viewport` 上，而不是滚动内容里面。
- 技能选择器只列本机能读到的目录；技能本体由 CLI 自己按触发词决定用不用，插件不代劳。
- 计划模式对 Codex 是指令；它可能没照做（模型行为），界面写明了这一点，不假装是开关。
- 模型列表取自本机 CLI 配置，不是内置清单：
  - **Claude**：`~/.claude/settings.json` 里 `env.ANTHROPIC_DEFAULT_<别名>_MODEL` 定义了别名指向，菜单里显示成 `sonnet → dumate/qwen3.8-max`；「默认」一行右侧写出当前配置的模型。
  - **Codex**：`~/.codex/config.toml` 的 `model_catalog_json` 指向一份模型目录，逐个列出 `slug → 显示名`；没配目录时只剩「默认」。
  - 两个 CLI 都没有「列出全部可用模型」的接口，所以这里不假装有全集：读不到就只显示名字，绝不编造。
- Codex 0.170 在非交互模式下默认把 Windows 沙箱后端解析为 `disabled`，工作台会自动改用 `unelevated` 修复；若企业策略禁用了全部沙箱实现，只读/工作区写入会被标灰，需要切「完全访问」。
- 工作目录若以 8.3 短路径传入，工作台会展开成长路径，避免 unelevated 沙箱报 `split writable root sets`。
- macOS / Linux 未验证：沙箱自动覆盖只针对 Windows。
- 升级按钮执行 `npm install -g` 对应 CLI 的最新稳定版，需要网络与 npm 权限。
